
Upgrade: 约束求解器数值内核全面升级（2026/11/5）

1. 更新概述

本次更新针对几何约束求解器的数值稳定性与求解速度进行了全面升级，
核心目标是根治复杂约束场景（尤其是三个圆互相相切）拖动时的强烈抖动
与震荡问题——该问题在某个圆的半径趋于极小或极大值时尤为严重。

升级同时完成了三件事：
一是将导致抖动的交互层根因（拖动对齐吸附"红色参考线"）改为设置可选项；
二是重写 LM 数值内核，引入行归一化、Nielsen 自适应阻尼、拒绝步计算缓存
与拖动时间连续性模式，把拖动求解开销稳定在 60fps 帧预算之内；
三是消除约束函数与交点对象中的多处不连续跳变源（绝对值 kink、存在性闪烁）。

本次升级不引入任何新依赖（纯 NumPy，明确不引入 SciPy），不修改约束序列化
格式，GeometricConstraint 接口、求解器调用方式完全向后兼容。

2. 核心新增功能

2.1 LM 数值内核 v2（constraints/solver.py 重写）

- 行归一化：残差与雅可比按行范数归一，消除长度/角度约束量纲混杂
  导致的条件数失衡。
- λI 信赖域阻尼：正规方程改为 (JᵀJ + (λ+μ)I)δ = −JᵀF。
  ★ 历史修正（v2.1）：初版曾采用 Marquardt 对角阻尼 (JᵀJ + λ·diag)，
  发现在秩亏系统上会扭曲搜索方向（单约束对单点时步长被推离径向、
  偏向对残差无影响的切向，导致停滞），已改回 λI。本系统变量全为
  二维坐标（同量纲、无需列缩放）且通常秩亏，λI 可保证最小范数
  GN 方向与恒正定。
- Nielsen 增益比自适应 λ：替代旧版固定 ×10/×0.1 倍率。
- 拒绝步复用缓存：拒绝步只调 λ 重解线性方程组，不再全量重算残差与
  雅可比（旧版每次迭代含拒绝步都全量重组，病态场景的主要提速点）。
- 收敛判据与返回语义与旧版完全一致（原始残差范数、绝对容差、
  停滞兜底阈值 1e-3），上游过约束检测行为不变。

2.2 拖动时间连续性模式（drag_mode）

- Tikhonov 正则项：拖动求解最小化 ‖F(x)‖² + μ‖x − x_prev‖²，
  x_prev 为本帧开始时的坐标，μ 按 JᵀJ 对角均值自适应标定。
  抑制欠约束系统零空间漂移与帧间解的重新分配（三圆相切抖动的
  数值层主因），松手时的精确求解（quick=False）自动校正最终状态。
- λ 跨帧热启动：Document 缓存求解器实例，上一帧末 λ 作为下一帧初值
  （钳制在 [1e-6, 1e2]），帧间行为连续。
- 步长钳制：拖动单帧位移 ≤ 4×帧间拖动距离（max_step 参数），防止跳变。
- 帧节流：每个渲染帧至多一次求解（8ms 间隔），高频鼠标事件不再重复求解；
  首次 move 必解、松手必解，保证状态一致性。
- ★ 附带修复：吸附点（PointOnObject）拖动时原本缺失约束求解触发，已补齐。

2.3 参考线对齐吸附设置化（抖动交互层根因）

- 新增设置项 interaction.guide_snap_enabled（默认关闭）：拖动对齐吸附
  （红色虚线参考线）改为可选项，偏好设置"交互"页新增复选框
  "拖动对齐吸附（红色参考线）"。
- 开启状态下同步修复三个固有问题：
  ① 单阈值翻转：吸附/脱开由同一 12px 阈值判定 → 改为 12px 吸上、
  16px 脱开的滞回，消除边界高频翻转；
  ② 自吸附：排除被拖对象所在连通分量内的点（对象图双向 BFS）；
  ③ 移动目标反馈震荡：排除与被拖点约束耦合、每帧被求解器移动的点。
- 设置经 SettingsStore 深合并兼容旧文档，无需迁移代码。

2.4 约束 kink 平滑（雅可比跳变消除）

- 内切相切 |r1−r2| 与线圆相切 |cross| 在 0 处不可导，旧版用硬 sign，
  半径接近时雅可比方向逐帧翻转 → 震荡。现改为平滑绝对值
  sqrt(v²+ε²)（ε=1e-6），残差与解析雅可比同步修改，序列化格式不变。
- 覆盖对象级约束（TangentCirclesConstraint/TangentLineCircleConstraint）
  与脚本点级约束（TangentCC/TangentCL）两套实现。

2.5 交点与链式法则稳定性

- IntersectPoint 存在性 3 帧滞回：相切临界处交点不再单帧闪烁
  （首次重算即决断，保证新建无效交点不误判；消失需连续 3 帧无解，
  期间位置冻结，避免下游级联跳变）。
- _fallback_solve 补圆×圆分支：修复 ExprCircle/ThreePointCircle
  参与的圆圆求交静默返回空的 bug，has_solver 同步更新。
- chain_rule.py 的 det 奇异阈值按场景尺度归一（线×线/线×圆/圆×圆）。

2.6 回归测试与 A/B 基准

- 新增 tests/test_constraint_stability.py：三圆相切连续拖动
  （无震荡/无爆炸/路径长度有界）、内切 r1≈r2 kink 平滑、
  极端小半径（1e-5）不崩溃、单帧求解预算冒烟（<30ms，目标 ≤8ms）。
- 新增独立脚本 benchmark_solver.py：内嵌 v1 求解器作为对照组，
  覆盖拖动单帧耗时、抖动指标、规模扩展、拒绝路径压力、帧节流模拟
  五个维度的 A/B 对比。

4. 验证与使用示例

示例 1：手动验证抖动根治
画三个圆并两两添加外切约束，拖动其中一个圆的圆心做快速、大幅、
往返拖动，并把半径拖到很大/很小：图形应平滑跟随，无高频震荡；
松手瞬间允许一次轻微"归位"（拖动中的连续性偏置被精确求解校正，
属预期行为）。

示例 2：参考线吸附开关
偏好设置 → 交互 → "拖动对齐吸附（红色参考线）"：
默认关闭；开启后吸附带 12px/16px 滞回，且不会吸附到被拖图形
自身的点或正在被约束驱动的点。


5. 兼容性与已知问题

- 向后兼容：GeometricConstraint 接口、ConstraintSolver 构造签名、
  solve / solve_constraints 旧调用方式、约束序列化格式（dump/build）
  全部不变；新能力均为新增可选参数/新增设置键，旧文档加载自动取默认值。
- 已知基线失败（测试用例自身设计问题，非本次升级引入）：
  test_constraint_drag.py::TestDragFreePoint::test_segment_distance_maintained
  test_constraint_drag.py::TestDragFreePoint::test_multiple_drag_frames
  （后者在部分环境下可能因求解器改进转为通过，属正常）。
- 性能预期：高回报鼠标下拖动求解次数减少 2–8 倍（帧节流）；病态场景
  单次求解快 2–5 倍（拒绝步缓存）；常规拖动迭代数从 5–12 降至 2–5；
  稳定图形的小幅拖动单帧 <0.1ms（近收敛快速退出）。
